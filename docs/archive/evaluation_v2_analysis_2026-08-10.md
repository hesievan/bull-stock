# A股牛市热度指数 · V2 引擎深度评估

> 评估日期：2026-08-10
> 评估对象：当前生产的 V2 引擎（`src/indicators/heat_index_v2.py`，9 指标 / 4 维度 + 展示型 QVIX 恐慌指数）
> 评估范围：计算过程、指标选择、数据来源、工程实现、主要风险与改进建议
> 说明：仓库内 `data/evaluation_report.md` 与 `docs/` 下多份报告描述的是**已废弃的 V1/baostock 架构**（19 指标、6 维度、baostock 数据源），与当前代码不符，本文以**现行 V2 代码**为准。

## 一、整体架构与计算方法

### 1.1 计算流水线（每日 `run_daily.py`）

```
原始数据(tushare/akshare/optbbs)
   │
   ├─ S1/S2/S3…  拉取 + 预计算表(daily_turnover / daily_new_high / daily_ma_alignment / index_daily_pe / stock_market_cap / daily_circ_mv …)
   │
   ▼
S5_calc  compute_index_v2  —— 9 个指标各自：原始值 → 10年历史百分位(0~100分)
   │
   ├─ 背离惩罚：情绪背离(换手率高+指数跌)、新高顶背离(指数涨+新高占比降)
   │
   ├─ 维度分 = 维度内指标按权重加权（再归一化）
   ├─ 综合分 = 9 指标按权重加权（再归一化）
   │
   ▼
S6 json_writer：3 日移动平均平滑 → 四区间分级(绿/黄/橙/红) → 写 JSON
   │
   ├─ S55 七大指数过热预判（独立，PE/PB 仅沪深300/创业板可用）
   ├─ S7  证监会行业板块热度
   ├─ S75 申万一级 6 大重点行业热度
   └─ S9  飞书/Bark 推送
```

核心方法论是**「历史百分位复合指数」**（percentile-rank composite），与 CNN Fear & Greed 等成熟情绪指数同构：每个指标转化为「当前值在过去 10 年中的分位」，再加权合成。思路透明、可解释、可回测，是**合理且标准**的做法。

### 1.2 指标与权重（v2_engine.weights，YAML 为唯一事实源）

| 维度(目标权重) | 指标 | 权重 | 方向 | 计算口径 |
|---|---|---|---|---|
| 估值 40% | 大盘PE | 14% | 高=贵=热 | HS300+ZZ500 成分股 PE(TTM) 中位数 → 10年分位 |
| | ERP | 13% | 低=贵=热 | 1/PE中位数 − 10Y国债收益率 → 分位反向 |
| | 巴菲特指标 | 13% | 高=贵=热 | 全市场总市值 ÷ 上一年度GDP → 10年分位 |
| 资金 30% | 两融余额市值比 | 15% | 高=热 | (融资+融券)÷流通市值，85%分位起饱和收敛 |
| | 存款市值比 | 15% | 低=热 | M2 ÷ 全市场总市值（月度）→ 分位反向 |
| 情绪 20% | 成交额M2比 | 10% | 高=热 | 日成交额 ÷ M2 → 10年分位 |
| | 换手率 | 10% | 高=热 | Σ成交额÷Σ流通市值×10 → 10年分位 |
| 结构 10% | 创新高占比 | 6% | 高=健康 | 距250日最高≤2%的股票占比 → 10年分位 |
| | MA排列比 | 4% | 高=健康 | MA20>MA60>MA120 多头排列占比 → 10年分位 |

> 维度目标权重 = 该维度内指标权重之和（估值 0.14+0.13+0.13=0.40，资金 0.30，情绪 0.20，结构 0.10），与 README/配置一致 ✅。

## 二、指标选择评估

### 2.1 优点

- **维度覆盖均衡**：估值 / 资金 / 情绪 / 结构四位一体，兼顾「贵不贵、钱多不多、人气旺不旺、内部分布健康否」。
- **方向处理一致**：所有指标均统一为「分数高=市场越热」，便于合成与解读。
- **结构类指标用「广度」而非「点位」**：创新高占比、MA 多头排列比衡量市场宽度（breadth），比单纯看指数点位更能反映牛熊内部结构，是专业做法。
- **两融饱和收敛**（F4 修复）与**PE 成分过滤**（F5 修复）是针对 A 股数据特征的有效工程修正。
- **背离惩罚**机制（情绪背离、新高顶背离）引入了「价量/结构矛盾」的二阶判断，超出简单分位合成，设计用心。

### 2.2 核心缺陷：指标高度相关，9 指标实际由少数原始信号驱动

这是**最值得重视的方法论问题**。逐项拆解可以发现，9 个指标的真实信息来源高度集中：

1. **PE 与 ERP 同源**：两者都由同一个 `pe_med`（PE 中位数）算出。ERP = 1/PE − 国债，是 PE 的单调变换。二者仅在「国债收益率变动」时才会分化。因此估值维度 27% 的权重本质上由 **pe_med 单一信号**主导。
2. **巴菲特指标 与 存款市值比 代数相关**：`存款市值比 × 巴菲特指标 = M2 / GDP`（近似常数）。由于 M2/GDP 缓慢漂移，二者近似互为反向，**强相关**。资金维度 15% + 估值维度 13% = **28% 的权重都绕不开「全市场总市值 total_mv」**。
3. 综合结果：**约 55% 的综合权重由 pe_med 与 total_mv 两个原始量驱动**（各出现两次，一次直接、一次经变换），9 指标的「分散化」表象弱于实际。

> 影响：指数对「估值抬升」和「市值膨胀」过度敏感，对情绪/结构类真实独立信号（换手率、成交额M2比、创新高、MA排列，合计仅 30%）相对压缩。回测中 2026-06 两融市值比处 10 年 99.6% 分位即能把综合分直接顶到红区（74 分），正是 total_mv 类信号权重过重的体现。

### 2.3 其它指标层面问题

| 问题 | 说明 | 严重性 |
|---|---|---|
| 「大盘PE」名不副实 | `update_index_daily_pe` 仅取 **HS300+ZZ500 成分股**（当前 n≈722）的中位数，并非「全市场」。README 写「全市场PE中位数」与代码不符。对中小盘覆盖不足。 | 中 |
| 换手率单位失真 | `cur_rate = Σamount/Σcirc_mv × 10`，×10 使报告值偏离真实换手率（分位比较中常数可约去，故**不影响打分**，但前端展示数值误导）。 | 低 |
| 估值权重 40% 偏高 | 相对 CNN 等同类指数，估值占比偏大；叠加 2.2 的同源问题，指数偏「慢变量」。 | 中 |
| 情绪背离触发苛刻 | 仅当 `turnover_score > 70` 才检查背离，阈值偏高，实战中很少触发。 | 低 |
| 缺失指标再归一化 | 某指标为 None 时剩余指标权重整体上浮，可能掩盖数据缺口带来的偏移。 | 低 |

## 三、计算过程评估

### 3.1 百分位函数不一致（代码一致性缺陷）

- `heat_index_v2.py` 自带 `_pct_rank`（第 101 行），使用**严格小于 `<`**：`sum(x < value)/len`。
- `utils._pct_rank`（第 37 行）、`index_heat.py`、`focus_industries.py`、`sector_calculator.py` 统一使用**含自身 `<=`**。
- 工作记忆与 TODO 均声称「已统一为 `<=`」，但 **V2 引擎并未迁移**，仍用 `<`；`test_heat_index_v2.py:67` 还断言了 `<` 行为（`_pct_rank([1,2,3,4,5],3)==0.4`）。

> 实质性影响很小（大样本下 `<` 与 `<=` 分位差 ≈ 0.5/n，对综合分 <1 分），但属于**未完成的「统一」改造**，且 false 地写在文档/记忆里，属于应清理的技术债。

### 3.2 配置中有「死配置」（误导风险）

- `config/*.yaml` 的 `dimension_weights`（valuation 0.25 / macro 0.15 / capital 0.15 / sentiment 0.20 / technical 0.10 / structure 0.15）是 **V1 遗留的 6 维度方案，V2 引擎从不读取**（V2 用 `INDICATOR_WEIGHTS` 并按指标聚合出维度分）。
- `data.lookback_years: 10` 与 `data.min_history_days: 250` 同样**未被 V2 引擎使用**——V2 在代码里硬编码 10 年窗口，历史样本门槛用 60/120 天而非 250。

> 这些字段会让维护者误以为可调，改了却无效。建议删除或显式标注「V1 遗留/未启用」。

### 3.3 「10年历史百分位」对 PE 实际被截断

`calc_pe` 用 `n_stocks` 过滤历史：当前 n≥600 时，只保留历史 n∈[max(0.5n,450), 1.5n]。早期（2015–2016，n≈100–500）记录在现代日期被**整体排除**，导致 PE 分位的实际回溯窗口远小于 10 年（可能只到 2016 年之后）。这是有意的口径一致性处理，但 README 仍声称「10年历史百分位」，存在透明度问题。

### 3.4 平滑与分级

- 3 日移动平均在 `json_writer.save_results_v2` 内基于 `history.json` 做（取最近 2 天 + 当日）。简单、无前视泄漏，合理。
- 分级阈值（绿<40 / 黄40–55 / 橙55–65 / 红65+）来自配置，与引擎解耦，便于调整。
- 通知防抖 `analyze_state` 用的是**未平滑的 `level`**，而前端展示用 `level_smoothed`，二者口径略有差异（可接受，但建议注明）。

## 四、数据来源评估

### 4.1 数据源清单与可靠性

| 数据 | 来源 | 可靠性 | 备注 |
|---|---|---|---|
| 全市场日K线+PE/PB/市值 | tushare `daily`+`daily_basic` | ⭐⭐⭐⭐⭐ | 需 2000+ 积分；单点故障风险 |
| 指数日行情 | tushare `index_daily`（失败回退 akshare） | ⭐⭐⭐⭐ | 双源兜底，好 |
| 融资融券 | tushare `margin`（沪深北三市合并） | ⭐⭐⭐⭐ | 已修复为三市合并 |
| M2 月度 | tushare `cn_m` | ⭐⭐⭐⭐ | 注：README 写「akshare M2」，**代码实为 tushare**，文档不符 |
| 国债收益率(10Y) | akshare `bond_zh_us_rate` | ⭐⭐⭐⭐ | 仅 2018-12 起有连续数据 |
| 申万行业分类 | akshare `index_component_sw` | ⭐⭐⭐ | akshare 接口稳定性一般 |
| 重点行业指数/估值 | akshare `index_hist_sw` + `sw_index_first_info` | ⭐⭐⭐ | 每日实时拉取，受 akshare 限流影响 |
| QVIX 恐慌指数 | optbbs.com CSV（CFFEX 股指期权） | ⭐⭐⭐ | **单源、硬编码列索引(19–28等)、2019-12 起、无回退** |
| 证监会行业分类 | tushare `stock_basic` | ⭐⭐⭐⭐ | — |
| 指数 PE/PB 历史 | tushare `index_dailybasic` | ⭐⭐ | **频率限制 1次/分钟，极易失败** |

### 4.2 关键数据风险

1. **指数过热预判的估值维度脆弱（重要）**
   `index_heat.py` 读取 `index_pe_history` 表来给沪深300/创业板做 PE/PB 估值评分。但**每日流水线 `run_daily.py` 从不写入该表**——它只由 `scripts/backfill_index_heat_history.py` 手工回填，且依赖 `index_dailybasic`（1次/分钟）。后果：
   - 若未做回填，沪深300/创业板指也退化为**纯技术评分**，与文档「50%技术+50%估值」不符；
   - 即使回填，`fix-plan` 已证实该表仅含 5 个指数代码（缺中证红利 sh000922），且抓取频繁撞频限。
   - 建议：将 `index_pe_history` 增量更新纳入每日流水线（带频限节流），或明确标注其为「离线回填、非实时」。

2. **QVIX 单源硬编码列索引**
   `qvix_fetcher.py` 按固定列号（如 300index 取 17–20 列）从第三方 CSV 提取。上游改版即静默错配（虽有 `EXPECTED_QVIX_COLUMNS=83` 守卫，但仅校验列数不校验位置）。且该指数**仅展示不计分**，故影响有限，但仍建议增加第二数据源或结构校验。

3. **tushare 单点依赖**
   核心行情、市值、两融、M2、行业分类全部依赖 tushare + 2000+ 积分。一旦 token 失效或积分不足，主指数停摆（指数行情有 akshare 兜底，但全市场 stock_daily 无兜底）。属架构性单点风险。

4. **akshare 接口稳定性**
   重点行业、申万分类、国债收益率依赖 akshare，其接口常因上游改版失效，且 `focus_industries._fetch_index_data` 每次实时拉全量历史再取末行，效率一般。

5. **文档与代码多处不符**
   - M2 来源（README 说 akshare，代码用 tushare）；
   - 「全市场PE」实为 HS300+ZZ500；
   - `dimension_weights` 等死配置；
   - `evaluation_report.md` 描述的是已废弃的 V1/baostock 架构，会严重误导新读者。

## 五、工程实现评估

### 优点
- **测试充分**：79 个单元测试（V2 引擎 37 个），覆盖核心计算与配置。
- **容错设计好**：每个 Step 独立 try/except，单步失败不阻断；预计算表缺失有 fallback 直查。
- **配置驱动**：权重/阈值/参数全部 YAML 化，便于回测与调参。
- **原子写入 + 种子库**：JSON 原子写避免半截文件；CI 用 seed-db 压缩库增量更新，工程化成熟。
- **可回测**：有 `backfill_*` 与回测脚本，支持历史重算（但回测未纳入 CI 自动校验，见下）。

### 待改进
- 回测未自动化进 CI（旧报告 P2-11 仍未落实）。
- `index_pe_history` 未接入每日流水线（见 4.2-1）。
- 存在 V1 残留文档/报告未清理，易误导。
- 死配置未清理（见 3.2）。

## 六、综合结论与优先级建议

### 总体评价
**方法论正确、工程扎实、可解释性强**，是一个达到「可用」水平的牛市情绪指数。主要短板不在「算错」，而在**指标同源导致信号集中**（pe_med + total_mv 合计约 55% 权重）以及**部分数据链路脆弱/文档失实**。

### 改进优先级

**P0（建议在采用为决策依据前处理）**
1. 正视指标同源：考虑对估值/资金维度做「去相关」——例如将 PE 与 ERP 合并为一个估值分、将巴菲特与存款市值比合并为一个市值分，再与真正独立的情绪/结构信号重新分配权重；或改用主成分/等权去同源。
2. 将 `index_pe_history` 增量更新接入每日流水线（带频限），并补齐中证红利等缺失代码，否则指数过热预判的估值维度名不副实。

**P1（建议修复）**
3. 清理死配置（`dimension_weights`、`min_history_days`、`lookback_years` 中未生效项）与 V1 残留文档（`data/evaluation_report.md` 等），避免误导。
4. 统一 `_pct_rank` 约定：将 `heat_index_v2.py` 的局部 `<` 实现改为复用 `utils._pct_rank`（并同步更新测试断言），兑现「统一」承诺。
5. 校正文档：M2 真实来源、PE 实为 HS300+ZZ500、QVIX 仅展示、指数估值依赖离线回填。

**P2（优化）**
6. 回测脚本纳入 CI，代码变更自动校验牛熊信号方向。
7. QVIX 增加结构/第二源校验；降低情绪背离触发阈值使其更具实战意义。
8. 评估「估值 40%」权重是否下调，给独立情绪/结构信号更大空间。

### 一句话总结
> 这是一个**架构清晰、计算透明、工程成熟**的牛市热度指数，但「9 指标/4 维度」的外壳下信号其实高度集中于 **PE 中位数**与**全市场总市值**两条原始序列；在补齐指数估值数据链路、清理同源冗余与失实文档后，可作为离场/减仓参考的可靠工具。
