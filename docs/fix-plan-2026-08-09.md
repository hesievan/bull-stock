#### F2（问题 2）情绪背离双重扣分 bug 【🔴 高优先级，第一项执行】

**现状**（`heat_index_v2.py` L776–781）：`penalty = 0.2`，循环对 `turnover_m2` 和 `turnover` 各扣 20 分，实际扣 40 分，与 README「最多 20 分」不符。

**方案（推荐 B）**：只扣触发指标 `turnover`（换手率本身），移除 `turnover_m2` 的扣减：

```python
for key in ("turnover",):  # 只扣触发背离的换手率，总额=20分
    if sentiment_scores.get(key) is not None:
        sentiment_scores[key] = max(0, sentiment_scores[key] - penalty * 100)
```

**理由**：
- 触发条件本身就是 `turnover_score > 70`（量价背离），惩罚应落在触发指标上，语义最清晰；
- 综合分影响从 -4 分修正为 -2 分，与「最多 20 分」的文档描述一致；
- 同步更新 `DIVERGENCE_CONFIG` 中 `penalty_factor` 的注释说明。

> 备选方案 A（按权重在流动性指标间分摊 20 分）——**不推荐**：报告给出的 A 方案代码有误（`sentiment_scores` 只含 `turnover_m2/turnover`，却按 `["turnover","margin_ratio","ma_alignment"]` 权重分摊，会退化为全扣 turnover），且复杂度过高、收益为零。

**验收标准**：
- 单测：`_apply_sentiment_divergence` 在触发条件下 `turnover` 扣 20 分、`turnover_m2` 不变、总分不穿 0；
- 回测对比：2024-10-08 等触发日综合分较修复前上升 ≈2 分（不再双重扣）。

#### F4（问题 4）两融余额市值比高分位倒 V 递减 【🟠 中优先级】

**现状**（L322–326）：`pct > 0.9` 时 `score = 900 * (1 - pct)`，pct=0.95 时骤降至 45 分——杠杆越高热度分反而越低，与「顶部预警工具指标单调递增」原则矛盾。

**方案（推荐 A：平滑饱和）**：

```python
import math
if pct <= 0.85:
    score = pct * 100
else:
    saturation = 15  # 0.85以上额外可用的饱和度
    adjusted = 0.85 + saturation * (1 - math.exp(-(pct - 0.85) * 20))
    score = adjusted * 100
# 结果: 0.85→85, 0.90→~92, 0.95→~95, 0.99→~98 —— 单调递增且平滑
score = min(score, 100)
```

**理由**：单调递增（与设计理念一致）+ 平滑（无突变）；`max_score` 阈值（95）预留到 F7 配置化。

**验收标准**：
- 单测：pct ∈ {0.80, 0.85, 0.90, 0.95, 0.99} 分数单调不减，且 0.95 分位 ≥ 90；
- 回测：2015 年杠杆极值日分数不再骤降。

**回归测试**：`test_margin_ratio_monotonic_above_90th`

#### F1 + F8（问题 1 + 问题 8）创新高占比改历史百分位 + 背离去重复用

**核心洞察**：问题 1 与问题 8 必须**合并解决**——报告给出的逐日 250 日窗口 SQL 直接跑 10 年 = 小时级，不可接受。正确做法是新建**预计算表 `daily_new_high`**（与 `daily_ma_alignment` 同一架构模式），一举解决：

- F1：百分位打分需要 10 年历史序列 → 查表即可；
- F8：顶背离需要当日/20 天前的新高占比 → 查表两次即可，消灭 4 次全量查询。

##### 步骤 1：建表（`src/data/database.py`）

在 `init_database` 的 CREATE TABLE 区新增（跟随 `daily_ma_alignment` 的注册方式，并加入预计算表陈旧检测清单）：

```sql
CREATE TABLE IF NOT EXISTS daily_new_high (
    trade_date TEXT PRIMARY KEY,
    new_high_ratio REAL,     -- 当日250日新高占比 (0~1)
    n_stocks INTEGER         -- 参与计算的股票数
);
```

##### 步骤 2：单日计算函数（`database.py`，仿 `compute_daily_ma_alignment` L691–731）

```python
def compute_daily_new_high(trade_date: str, db_path: str = None) -> bool:
    """计算单日 250 日新高占比并写入 daily_new_high"""
    with get_conn(db_path) as conn:
        target = pd.read_sql(
            "SELECT stock_code FROM stock_daily WHERE trade_date=? AND close > 0",
            conn, params=[trade_date])
        if target.empty or len(target) < 100:
            return False
        min_date = (pd.Timestamp(trade_date) - pd.DateOffset(days=400)).strftime("%Y-%m-%d")
        hist = pd.read_sql(
            "SELECT stock_code, trade_date, close FROM stock_daily "
            "WHERE trade_date BETWEEN ? AND ? AND close > 0 ORDER BY stock_code, trade_date",
            conn, params=(min_date, trade_date))
        # 每只股票 250 日窗口内最高收盘价 → 用滚动 max 而非逐日子查询
        def _max_close(g):
            g = g.sort_values("trade_date")
            s = g["close"].values
            return np.max(s[-250:]) if len(s) > 0 else None
        max_close = hist.groupby("stock_code").apply(_max_close)
        today_close = hist[hist["trade_date"] == trade_date].set_index("stock_code")["close"]
        valid = today_close.dropna()
        merged = pd.DataFrame({"close": valid})
        merged["max_close"] = max_close.reindex(valid.index)
        merged = merged.dropna()
        if len(merged) < 100:
            return False
        ratio = float((merged["close"] >= merged["max_close"] * NEW_HIGH_THRESHOLD).mean())
        conn.execute(
            "INSERT OR REPLACE INTO daily_new_high (trade_date, new_high_ratio, n_stocks) VALUES (?, ?, ?)",
            (trade_date, round(ratio, 6), len(merged)))
        return True
```

> 性能提示：单日计算需扫 400 日 × 全市场股票，与 `compute_daily_ma_alignment` 同量级（3s/日）。10 年回填 ≈ 2500 天 × 3s ≈ **2 小时左右**，建议作为一次性后台任务执行，避开 CI 时段。优化项（可选）：按股票滚动 max 一次性生成全部日期的占比，可将回填降到分钟级——若采用，`daily_new_high` 直接整表重建。

#### F10（问题 10）维度分与综合分口径统一 【🟡 低优先级】

**现状**（L700–707）：维度分 = 维度内等权平均；综合分 = 按 `INDICATOR_WEIGHTS` 加权。同一维度两套分数，展示易误解。

**方案（推荐 B：维度分也按指标权重）**：

```python
for dim_name in DIMENSIONS:
    ind_keys = [k for k, v in INDICATOR_DIMENSIONS.items() if v == dim_name]
    available = [(k, scores[k]) for k in ind_keys if scores[k] is not None]
    if not available:
        dim_scores[dim_name] = None
        continue
    w = sum(INDICATOR_WEIGHTS[k] for k, _ in available)
    dim_scores[dim_name] = sum(v * INDICATOR_WEIGHTS[k] for k, v in available) / w
```

**效果**：维度分 × 维度权重 = 该维度对综合分的实际贡献，彻底消除两套口径。展示文件 `index.json`/`detail.json` 的维度分会变化（数值更贴近真实贡献），**前端 app.html 无需改动（只读分数），但需确认飞书通知文案不含维度分**。

**验收标准**：单测验证 `Σ(维度分 × 维度权重) ≈ 综合分`（容差 0.1）；回测记录维度分变化。

**回归测试**：`test_dimension_scores_weighted_consistent_with_composite`
